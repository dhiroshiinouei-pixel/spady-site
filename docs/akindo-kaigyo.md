# AKINDO Lab｜開業準備 MVP

追加先は既存のAstro 5プロジェクト `spady-site-publish`。静的出力のみで、依存パッケージ・サーバー・ログイン・データベースは追加していません。

## ページ

- `/akindo/kaigyo/`：現在地、5段階のロードマップ、困りごと、業種、道具、相談・勉強会への入口。
- `/akindo/kaigyo/checklist/`：20項目の状態変更、6フェーズ（開業前5段階＋開業後）、未完了絞り込み、進捗、再開、確認付きリセット。
- `/akindo/kaigyo/diagnosis/`：8問・4ステップのルールベース診断。3段階の優先度、理由、予算・設定スキル別の案内。
- `/akindo/kaigyo/tools/`：10カテゴリの選択肢。`?category=reservation` のカテゴリ絞り込みと `#stores-reserve` などの直接リンク。
- `/akindo/kaigyo/start/salon/`：13の準備・改善テーマとチェックリスト、診断への入口。各テーマに「今日の一歩」。

既存 `/akindo/` は勉強会・活動紹介のまま保持。フッターのリンク1件のみ追加。既存robotsのAllow設定は維持。2026-11-07のテスト公開では5URLをサイトマップから除外し、noindexをHTMLとHTTPヘッダーに設定しています。

## 主な構造

- `src/layouts/KaigyoLayout.astro`：専用の共通レイアウト、SEO、パンくず、WebPage/BreadcrumbList。既存の3D演出・GTMは読み込みません。
- `src/styles/akindo-kaigyo.css`：デザイントークン、レスポンシブ、共通部品。各機能の追加スタイルはAstroコンポーネントにスコープ。
- `src/components/akindo/kaigyo/`：ヘッダー・フッター、トップの各セクション、3つの操作UI。
- `src/data/akindo/`：チェックリスト、診断質問/ルール、ツール、業種、サロンガイド、共通URL。
- `src/scripts/akindo-checklist.ts` / `akindo-diagnosis.ts`：ブラウザ内の状態管理と操作。その他メニュー・ツール絞り込みは該当コンポーネント内。

## 保存・操作

LocalStorageのキーは `akindo_kaigyo_progress_v1`。保存内容は `{項目id: 状態}` のみで、名前・メール・顧客情報・診断回答は保存しません。状態は `not_started` / `in_progress` / `completed`。完了だけを進捗率に含めます。読めない値は未着手として扱い、保存不可でもページ内の操作は続けられます。端末・ブラウザをまたぐ同期はありません。

JavaScriptを無効にしてもチェック項目とツール一覧は読めます。診断にはJavaScriptが必要と明示しています。メニューはネイティブdetails、状態はaria-pressed付きボタン、診断はfieldset/legend付きラジオ、リセットはキャンセルを初期フォーカスにしたdialogを使用します。

## データ追加

チェック項目は `checklist.ts` の `checklistItems` に追加します。idは保存データと対応するため、公開後は安易に変更しないでください。件数と進捗率は自動算出されます。

ツールは `tools.ts` の `tools`、カテゴリは `toolCategories` に追加します。未確認の価格・無料プランは書かず、`freePlan: null` を使用します。`lastVerified` は公式URLの確認日であり、価格保証ではありません。`affiliateUrl` を設定した場合、画面は広告リンクを明示し `rel="sponsored nofollow"` を付けます。L Message（エルメ）とエルグラムには、ユーザー提供のアフィリエイトURLを設定しています。ページ上部と各カードに広告表記を出し、紹介コードを含まない公式URLも併記しています。銀行・カードは特定サービスを選定せず、確認中の一般的な選び方として掲載しています。

業種は `industries.ts` に追加します。詳細未作成の業種は、準備中と明示した共通チェックリストへのリンクです。診断は `diagnosis.ts` に質問・条件・理由をまとめています。

## デザインと素材

既存AKINDO Labの白・温かいグレー・深緑と地域事業者への姿勢を継承。マスタードは次の行動、深緑は進捗・思想を示す色として使用。システムフォントのみで新しいWebフォントはありません。

FAVTOWN（https://www.favtown.jp/）の「大きなコンセプト、ステータスで整理したカード、機能と思想の両方を伝える構成」を参照しました。文章、HTML、CSS、写真、ロゴ、装飾は転用していません。進捗カードはオリジナルのHTML/CSSで「利用イメージ」と表示。勉強会写真は既存の所有素材をリサイズしたWebPです。今回、内蔵imagegenで商店街・準備ノート・サロンのイラスト3点を制作し、独自SVGの準備図解・カテゴリ図解・顧客導線を追加しました。[画像の制作記録](kaigyo-image-prompts.md)に原寸・配信用画像・正確なプロンプトを保存しています。

LINEのURLは `public/akindo/index.html` に存在するリンクを `site.ts` にそのまま移しています。ツールとサロンの公式参照先はデータ内に記録しています。

## 起動・検証

通常のNode/npm環境：

```sh
npm run dev -- --host 127.0.0.1 --port 4328
npm run check:release
```

ビルド済み静的サイトの確認：

```sh
python3 -m http.server 4328 --bind 127.0.0.1 --directory dist
```

新しい診断の回帰テストは既存 `npm test` に含まれます。全17,496通りを走査し、8問すべてが結果へ反映されることを確認します。既存同様、Node 24相当のTypeScript strip機能が必要です。

任意のブラウザQA：既存環境のPlaywrightとChromeを使用し、本番依存には追加しません。

```sh
node scripts/verify-kaigyo.mjs
```

`PREVIEW_URL` の既定値は `http://127.0.0.1:4328`。検証用ブラウザの独立したコンテキストだけに進捗を保存し、問い合わせ送信やLINE登録は実行しません。結果と画像は `artifacts/kaigyo-review/`（Git対象外）に保存されます。

既存の勉強会写真・OGPを再書き出しする場合は、既存のsharpを参照して `node scripts/prepare-kaigyo-assets.mjs` を実行します。新しいイラストの生成方法・ファイルは [画像の制作記録](kaigyo-image-prompts.md)を参照してください。

## テスト公開（2026-11-07）

ユーザーの依頼に基づき、既存本番環境の `/akindo/kaigyo/` と4つの下層ページをテスト公開する構成です。全ページにテスト表示、titleの接頭辞、robots noindex/nofollowを設定。Cloudflare Pagesの`public/_headers`でも同範囲にX-Robots-Tagを付け、サイトマップから除外します。検索除外はアクセス制限ではなく、URLを知っている人は閲覧・操作できます。

正式公開へ切り替える際は `src/data/akindo/site.ts` の `kaigyoTestRelease` を false にし、`public/_headers` の開業準備向けルールと既存 `/akindo/` のテスト表記を外してください。テスト表示・robotsメタ・title接頭辞・サイトマップはフラグに連動します。
